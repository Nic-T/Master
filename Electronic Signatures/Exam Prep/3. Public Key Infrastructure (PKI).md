# Public Key Infrastructure (PKI)

## PKI Components

You should be able to identify roles within PKI:

- **Certification Authority (CA)**: The trusted third party that issues, renews, and revokes certificates; binds public keys to identities.
- **Registration Authority (RA)**: Optional front-end that verifies applicants' identities and approves requests; does not itself issue certificates or CRLs.
- **Repository**: Directory (LDAP/Web) where certificates and CRLs are published.
- **End Entity**: The subject of the certificate (user, server, device).

## Digital Certificates (X.509 v3)

Think of a certificate as an "information highway driver's license" that ties a public key to an identity.

- Key fields: Version, Serial Number, Signature Algorithm, Issuer, Validity (Not Before / Not After), Subject, Subject Public Key Info, Extensions (Key Usage, Subject Alternative Name, etc.).

## Trust Models

Trust is established via certification paths (chains):

- **Root CA**: Trust anchor; typically self-signed and kept offline for security.
- **Intermediate CA**: Issued by a root; used to issue end-entity certificates.
- **Cross-Certification**: Peer-to-peer trust between CAs (mesh) — can scale poorly.
- **Bridge CA**: Central hub that connects multiple PKI domains (e.g., Federal Bridge CA) to simplify trust relationships.
- **Trust Lists**: OS/browser trust stores and regulated lists (EUTL for EU Qualified TSPs).

## Validation & Revocation

A certificate can be cryptographically valid but administratively revoked. Common methods:

- **CRL (Certificate Revocation List)**: Periodically published signed lists of revoked serial numbers. High bandwidth; privacy-friendly.
- **OCSP (Online Certificate Status Protocol)**: Real-time query for a single certificate. Low bandwidth; privacy trade-offs; single-point-of-failure risk if unavailable.
- **Delta CRL**: Smaller CRL with only changes since the last base CRL.

Comparison summary:

- Timeliness: OCSP (real-time) vs CRL (periodic)
- Bandwidth: CRL (high) vs OCSP (low)
- Privacy: CRL (higher privacy) vs OCSP (lower)

## Timestamping

To prove a signature existed at a specific moment, use a Time Stamping Authority (TSA):

1. Signer hashes the document and sends the hash to the TSA.
2. TSA signs the hash with a timestamp (RFC 3161) and returns the token.
3. The token proves the document existed before the timestamp.

Exam tip: Encryption keys may be backed up for recovery; signing private keys must be protected to preserve non-repudiation (avoid escrow/backups by third parties).
