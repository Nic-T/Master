# 3. Transport layer security (SSL/TLS)

## Overview ✅

- **Layer:** Transport / Application boundary
- **History:** SSL (Netscape) → TLS (IETF standard)
- **Common ports:** `HTTPS` (443), `LDAPS` (636), `SMTPS` (465)
- **Rule of thumb:** Disable SSL; use **TLS 1.2+**

---

## Architecture — 4 sub-protocols 🔁

1. **Handshake Protocol**
   - Negotiates cipher suite & TLS version, authenticates server (optionally client)
   - Key steps: ClientHello → ServerHello → Certificate → KeyExchange → ChangeCipherSpec → Finished
   - Result: Master secret derived from pre-master + both nonces → generates session keys
   - Exam tip: Randoms prevent replay; master secret never transmitted

2. **Record Protocol**
   - Handles all data transmission: fragment → compress → MAC → encrypt → add header
   - Uses symmetric encryption (AES) on fragments (max 16 KB)
   - Exam tip: Sits below other protocols; processes everything

3. **Change Cipher Spec Protocol**
   - Single 1-byte message that activates negotiated parameters
   - Sent after key exchange, before Finished message
   - Exam tip: The "switch" — handshake plaintext before this, encrypted after

4. **Alert Protocol**
   - Communicates warnings (non-fatal, level 1) and errors (fatal, level 2)
   - Common: `close_notify`, `bad_certificate`, `handshake_failure`, `certificate_expired`
   - Exam tip: Fatal alerts terminate immediately; warnings may continue

---

## Attacks to know ⚠️

- **BEAST** (2011) — Exploits CBC mode in TLS 1.0; injects known plaintext to predict IVs
- **CRIME** (2012) — Compression side-channel; deduces secrets by observing compressed size changes
- **POODLE** (2014) — SSLv3 padding oracle; forces downgrade to SSLv3 then exploits CBC padding
- **Heartbleed** (2014) — OpenSSL buffer over-read; leaks private keys & memory contents (critical)
- **FREAK** (2015) — Forces weak "export-grade" RSA keys (512-bit); breaks encryption via factorization
- **Logjam** (2015) — Downgrade to weak DH parameters (512-bit); breaks key exchange
- **DROWN** (2016) — SSLv2 padding oracle cross-protocol attack; decrypts TLS sessions
- **Renegotiation** — MitM injects commands during handshake renegotiation (pre-2009 fix)

**Exam tips:**

- **CBC attacks:** BEAST, POODLE — mitigated by using AEAD ciphers (GCM)
- **Compression attacks:** CRIME — compression now disabled
- **Downgrade attacks:** POODLE, FREAK, DROWN — disable old protocols (SSLv2/v3)
- **Critical vulnerability:** Heartbleed — always associate with memory leak + private key exposure

---

## Quick exam tips 💡

- Be able to order the handshake steps and identify when keys are derived.
- Remember: certificates provide identity (PKI) and are validated during the handshake.

- **AES** — Advanced Encryption Standard
- **CBC** — Cipher Block Chaining
- **DH** — Diffie-Hellman
- **GCM** — Galois/Counter Mode
- **HTTPS** — Hypertext Transfer Protocol Secure
- **IETF** — Internet Engineering Task Force
- **IV** — Initialization Vector
- **LDAPS** — Lightweight Directory Access Protocol Secure
- **MAC** — Message Authentication Code
- **MitM** — Man-in-the-Middle
- **PKI** — Public Key Infrastructure
- **RSA** — Rivest-Shamir-Adleman
- **SMTPS** — Simple Mail Transfer Protocol Secure
- **SSL** — Secure Sockets Layer
