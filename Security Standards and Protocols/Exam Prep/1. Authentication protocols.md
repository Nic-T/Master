# 1. Authentication protocols

## Key concepts ✅

- **AAA model**
  - **Authentication** — prove who you are
  - **Authorization** — access rights
  - **Accounting** — logging and auditing

- **Authentication factors**
  1. **Something you know** — password, PIN
  2. **Something you have** — token, smart card, phone
  3. **Something you are** — biometrics (fingerprint, iris, voice)

- **Performance metrics**
  - **FAR (False Acceptance Rate)** — impostors accepted
  - **FRR (False Rejection Rate)** — valid users rejected
  - **EER (Equal Error Rate)** — point where FAR = FRR (system accuracy)

---

## Specific protocols (concise) 🔒

- `PAP` (Password Authentication Protocol)
  - Sends username/password in clear text — **vulnerable to sniffing**.
  - Exam tip: "PAP = Plaintext".

- `CHAP` (Challenge-Handshake Authentication Protocol)
  - 3-way handshake: server sends random **challenge** → client replies with **hash(challenge + password)** → server verifies
  - Password never sent; helps prevent replay attacks.

- `NTLM` (Windows NT LAN Manager)
  - Challenge–response used in Windows domains; relies on a Domain Controller (DC)
  - Vulnerable to **Pass-the-Hash** attacks (hash replay)

- `Kerberos`
  - Central trusted third party: **KDC** (Key Distribution Center)
  - Uses **tickets** (TGT = Ticket Granting Ticket) for service access
  - **Mutual authentication** and time-stamped messages — requires synchronized clocks
  - Exam tip: Kerberos = tickets + KDC + time sensitivity

---

## Quick exam tips 💡

- Classify examples by factor quickly (e.g., "retina scan" → _something you are_).
- Remember: **PAP = insecure**, **CHAP = challenge-response**, **Kerberos = tickets & KDC**.
- Know common vulnerabilities: **Pass-the-Hash** (NTLM), replay attacks (if no nonce/timestamp).
